# Add bounded opt-in worker runner bridge

## Objective

Automate worker intake and execution through a provider-neutral, explicitly enabled runner contract while preserving scope locks, report gates, finite cycle limits and no implicit external side effects.

## Acceptance criteria

- [ ] A registered worker may opt into a configured runner command with explicit assignment/task placeholders; the default behavior remains no external execution.
- [ ] A bounded worker run claims the oldest eligible assignment, invokes the configured runner without shell interpolation, and returns a clear result when the runner is absent, fails or omits its report.
- [ ] The runner bridge cannot escape the repository scope, bypass claim/report/review gates or run unbounded by default; tests cover success, failure, missing runner and scope safety.
- [ ] The mixed-runtime conformance harness exercises automatic intake with simulated Codex, Claude Code and Antigravity-style runners without vendor credentials.
- [ ] English/Vietnamese onboarding and autopilot docs explain one-time runner setup, provider limitations, safe defaults and how the supervisor consumes reports.
