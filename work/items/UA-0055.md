# Add worker runtime readiness and failure classification

## Objective

Add a provider-neutral, bounded worker runtime readiness contract and normalized dispatch/start failure classification so UseAgent avoids clearly unavailable runner dispatch, preserves truthful ownership and failure history, and gives supervisors safe retry/reassign/needs-input dispositions without guessing quota.

## Acceptance criteria

- [ ] Malformed or unavailable configured runners are classified before pull/dispatch and do not create ghost ownership or blind dispatch; manual/no-runner and legacy no-preflight behavior remain compatible.
- [ ] Optional argv-only adapter preflight returns normalized ready, unavailable, misconfigured/no_target, or unknown states with bounded timeout and sanitized/local-only diagnostics; readiness never claims quota certainty.
- [ ] Runner start failures use a provider-neutral machine-readable result contract; quota_limited and auth_error require authoritative adapter evidence, while ambiguous text is never classified as quota_limited.
- [ ] Pre-start failures preserve assigned task truth, runtime evidence, retry/reassign/takeover/needs-input disposition, and do not strand the workflow in unowned in_progress or report-wait dead ends.
- [ ] Existing runner/report, timeout, output hygiene, UA-0050 lineage, UA-0052 fingerprint, validator, and release behavior remain non-regressed.
- [ ] Document the runtime topology boundary, readiness/failure contract, ownership lifecycle, bounded retry policy, and provider adapter responsibilities.
