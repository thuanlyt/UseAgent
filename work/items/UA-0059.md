# Add provider-neutral usage telemetry and execution summaries

## Objective

Implement bounded provider-neutral telemetry and execution summaries for task, cycle and phase workflows with factual timing, participants, usage provenance, idempotent aggregation, privacy-safe output, and source-fingerprint-safe volatile storage. Do not build billing, dashboard, provider-specific parsers, or change OSBlog.

## Acceptance criteria

- [ ] Normalize explicit provider-neutral usage envelopes with authoritative, measured, estimated and unavailable provenance without guessing tokens.
- [ ] Record lifecycle duration, actual participants, retries and takeover lineage and aggregate without double-counting repeated events or parallel wall time.
- [ ] Keep raw diagnostics local, bounded and private while rendering a concise deterministic Usage section for owner reports.
- [ ] Keep telemetry writes outside release-source fingerprinting and preserve existing evidence freshness, runtime readiness, QA and release behavior.
- [ ] Add regression coverage for the required timing, usage, aggregation, privacy, provenance and non-regression scenarios.
- [ ] Document the contract and integration without claiming universal token tracking, billing or provider coupling.
