# Bind QA and release gates to source state

## Objective

Prevent successful QA and production/release readiness from reusing a PASS produced for a different source or QA configuration state, while excluding only documented volatile control-plane outputs.

## Acceptance criteria

- [ ] QA records a deterministic release-source fingerprint covering HEAD, tracked working-tree changes, relevant untracked source/config files, QA/release configuration and QA command contract.
- [ ] A successful QA result remains valid only when the current release-source fingerprint exactly matches its recorded fingerprint; source/config changes make the previous result stale without automatic rerun.
- [ ] The production/release gate recomputes and compares the current fingerprint, rejects stale QA explicitly, and does not let generated reports/evidence/checkpoints/runtime state self-invalidate a fresh QA result.
- [ ] Fingerprint provenance records status, fingerprint, HEAD, dirty-state equivalent, QA configuration/version, executed checks and timestamp while remaining compatible with UA-0049 typed provenance and UA-0051 safe evidence.
- [ ] Regression tests cover unchanged, source/test/config changes, dirty-state changes, volatile control-plane updates, rerun recovery, release-gate rejection and existing freshness/evidence behavior.
