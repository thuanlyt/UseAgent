# Make runner and QA output evidence-safe

## Objective

Prevent raw command, runner and supervisor QA output from becoming committable evidence by default while preserving bounded debugging references, typed provenance and existing lifecycle behavior.

## Acceptance criteria

- [ ] Runner and QA durable evidence stores only bounded safe summaries and metadata; raw runtime output is written to a separate local spool under work/.runtime-output.
- [ ] stdout and stderr use deterministic per-stream budgets and explicit truncation metadata; oversized output never expands committable evidence beyond the configured contract.
- [ ] Secret-like command/output values are redacted in durable summaries as defense-in-depth, and durable runner/QA evidence contains no raw token, password, API key, cookie, authorization, private key or credentialed URL.
- [ ] Local spool references remain useful for debugging, are repository-relative, are ignored by default, and existing tracked historical evidence is not deleted or rewritten.
- [ ] Runner, QA, report freshness and typed provenance behavior remain compatible and are covered by regression tests.
