# Add Git release durability gate and provenance

## Objective

Distinguish task completion, QA validity, local Git-backed release durability and optional upstream publication readiness; make the production/release snapshot fail closed for non-durable Git source while preserving local-first and non-Git behavior.

## Acceptance criteria

- [ ] Clean committed Git source with matching source-bound QA passes the local durability gate.
- [ ] Dirty tracked, staged, or non-ignored untracked release-source state fails strong durability without silently invalidating development QA semantics.
- [ ] Configured volatile control-plane writes do not fail local durability; historical evidence is not deleted or rewritten.
- [ ] A commit after QA changes source identity and requires QA rerun before strong release readiness; no smart reuse.
- [ ] Branch ahead/behind, upstream-known/unknown, and no-upstream cases are explicit metadata and do not couple readiness to origin/main or require network mutation.
- [ ] Non-Git workspaces have explicit degraded behavior and never claim strong Git durability.
- [ ] Regression coverage preserves UA-0051 evidence hygiene and UA-0052 source-bound QA semantics.
